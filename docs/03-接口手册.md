## 0. 网络

| 项 | 值 |
|---|---|
| P4 地址 | `192.168.1.10`（静态） |
| 掩码 / 网关 | `255.255.255.0` / `192.168.1.100`（PC） |
| 速率 | 100 Mbps 全双工（IP101GRI，RMII） |
| MAC | `e8:f6:0a:e8:cc:28` |

PC 侧网卡需设为同网段静态地址（`192.168.1.100/24`），否则 ping 不通。

## 1. HTTP 端点

| 端点 | 方法 | 作用 |
|---|---|---|
| `/` | GET | 网页控制台（编译时嵌入的 `index.html`） |
| `/status` | GET | 纯文本状态 ⚠️ **当前是残桩，见 §1.2** |
| `/stream` | GET | MJPEG 推流（multipart，异步 handler） |
| `/cam` | GET | 摄像头调参 |
| `/stm` | GET | STM32 遥测查询 / 命令下发 / 链路自测 |
| `/ai` | ANY | PC 推理结果入口 / 查询 / 开关 |
| `/time` | GET | 对时（PC 推 epoch） |
| `/sd` | GET | SD 文件列表（videos + logs） |

### 1.1 `/stream`

```
Content-Type: multipart/x-mixed-replace; boundary=frame

--frame\r\n
Content-Type: image/jpeg\r\n
Content-Length: <n>\r\n
\r\n
<jpeg 字节>
\r\n
```

**注意**：`esp_http_server` 用 `httpd_resp_send_chunk()` 发送，所以 HTTP 层是
`Transfer-Encoding: chunked`。自己写 socket 客户端要处理 chunked；
用 Python `http.client` / `urllib` 会自动解码，直接按 multipart 解析即可。

### 1.2 `/status`

当前返回（**写死的，不可信**）：

```
ip=192.168.1.10
netmask=255.255.255.0
free_heap=18998183
uptime_s=1509
camera=placeholder
sdcard=disabled
```

`camera=` 和 `sdcard=` 是早期骨架的占位字符串，**不反映真实状态**。
需要看真实状态请用 `/sd`、`/stm`、串口日志。

### 1.3 `/cam`

| 参数 | 范围 | 说明 |
|---|---|---|
| `info=1` | — | 返回当前曝光/增益/目标亮度/VTS 等 JSON |
| `exp=N` | 2~3596 | 曝光行数（`tline`×N 即时间，N=3596 ≈ 99.9 ms） |
| `gain=N` | 16~1023 | 增益，**16 = 1.0×** |
| `auto=1/0` | — | 开/关软件测光 |
| `target=N` | 20~200 | 测光目标亮度（绿色通道均值） |
| `lock=1` | — | 锁定当前曝光/增益 |
| `vts=N` | 1120~65535 | **帧率 = 36000/N**（3600 → 10 fps，1199 → 30 fps） |

```bash
curl "http://192.168.1.10/cam?info=1"
curl "http://192.168.1.10/cam?vts=3600"     # 切 10fps，曝光上限 100ms
curl "http://192.168.1.10/cam?exp=3000&auto=0"
```

### 1.4 `/stm`

| 参数 | 说明 |
|---|---|
| `raw=1` | 返回最近若干条**原始行**（排障用） |
| `loop=1` | 回环自测：P4 自发自收，验证 TX/RX 都通 |
| `ping=1` | 发一次 ping |
| `diag=1` | 打一份链路统计（rx / bad / half / 跳变次数） |
| `mode=N` | 下发模式切换 |
| `set_temp=24.5` | 设置目标温度 |
| `set_humi=70` | 设置目标湿度 |
| `light_level=0~4` | 补光档位（**每扇区点亮几颗**，不是百分比） |
| `all_off=1` | 全部执行器关闭 |

```bash
curl "http://192.168.1.10/stm"              # 当前遥测 JSON
curl "http://192.168.1.10/stm?raw=1"        # 最近原始行
curl "http://192.168.1.10/stm?loop=1"       # 回环自测
```

### 1.5 `/ai`

**上报（PC → P4）**：

```json
POST /ai
{"count": 42, "sick": 4, "motion": 0.12, "conf": 0.91, "sick_ratio": 0.095, "ts": 1762732800}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `count` | int | 当前蚕数 |
| `sick` | int | 病蚕数 |
| `sick_ratio` | float 0~1 | 病蚕占比（**不传则用 `sick/count` 推算**） |
| `motion` | float 0~1 | 异动指数 |
| `conf` | float 0~1 | 模型置信度，**< 0.50 直接不动作** |
| `ts` | int | 推理时间戳（epoch 秒） |

**查询（GET 同样字段名）**：

```bash
curl "http://192.168.1.10/ai"
curl "http://192.168.1.10/ai?count=42&sick=4&motion=0.1&conf=0.9"
curl "http://192.168.1.10/ai?enable=0"      # 关闭决策引擎（上报不算一次数据）
```

### 1.6 `/time`

```bash
curl "http://192.168.1.10/time?epoch=1762732800"
```

**必须调用，否则 SD 上的文件名是 `19700101_xxx.avi`**。
隔离局域网里 SNTP 找不到 NTP 服务器，会打一条 `SNTP: 对时失败` 警告后放弃。
网页控制台在加载时和每 10 分钟自动调一次；PC 脚本建议启动时也调一次。

### 1.7 `/sd`

返回 JSON：`videos[]` 与 `logs[]`，每项含文件名和**字节数**（字段名是 `bytes`，不是 KB）。

## 2. UART 协议（P4 ↔ STM32）

**物理层**：115200 8N1，**P4 GPIO22(TX) → PA3**，**P4 GPIO21(RX) ← PA2**，共地。

### 2.1 上行：STM32 → P4（遥测，每秒一行）

```json
{"type":"tele","seq":1234,"tin":24.6,"hin":68.2,"tout":19.1,"hout":55.0,
 "ah":12.3,"td":1.8,"tset":24.5,"rhset":70,"mode":2,
 "cool":0,"heat":1,"hum":0,"light":1,"fan":0,"tfan":1,"fault":0}
```

| 字段 | 含义 | 单位 |
|---|---|---|
| `seq` | 递增序号（判丢包） | — |
| `tin` / `hin` | 箱内温度 / 湿度 | °C / % |
| `tout` / `hout` | 箱外温度 / 湿度 | °C / % |
| `ah` | 绝对湿度 | g/m³ |
| `td` | 露点 | °C |
| `tset` / `rhset` | 目标温度 / 湿度 | °C / % |
| `mode` | 运行模式 | 枚举 |
| `cool` / `heat` | 制冷 / 制热 状态 | 0/1 |
| `hum` | 加湿（雾化）状态 | 0/1 |
| `light` / `light_level` / `light_leds` | 补光状态 / 档位 / 灯珠数 | — |
| `fan` / `tfan` | 循环风扇 / TEC/PTC 风扇 | 0/1 |
| `fault` | 故障位 | 位掩码 |

> 计划新增：`lr` / `lg` / `lb` —— 当前生效的补光 R/G/B（闭环反馈必需），见 `补光调色规范.md`。

### 2.2 下行：P4 → STM32（命令）

| JSON | 说明 |
|---|---|
| `{"ping":1}` | 心跳（每 5 s） |
| `{"version":1}` | 查固件版本（上电握手） |
| `{"status":1}` | 查完整状态 |
| `{"set_temp":24.5}` | 目标温度 |
| `{"set_humi":70}` | 目标湿度 |
| `{"light_level":0~4}` | **补光档位 = 每扇区点亮几颗灯**（⚠️ 不是百分比，见 §4） |
| `{"fan":0/1}` | 循环风扇 |
| `{"mode":N}` | 运行模式 |

> 计划新增：`{"light_r":255,"light_g":190,"light_b":110}` —— 见 `D:\stm32work\BS1\docs\补光调色规范.md`。

### 2.3 链路监控与判定

| 参数 | 值 | 作用 |
|---|---|---|
| 半帧超时 | 50 ms | 收到换行前超时 → 计 `half_frames` |
| 离线判定 | 3.5 s 无有效帧 | 标记离线，写 `LINK_LOST` 事件 |
| ping 周期 | 5 s | 主动探活 |
| 上电握手 | 1.5 s 后发 `version` + `status` | 确认链路 |
| 自诊断 | 开机 6 s | 见下表 |

| 现象 | 判定 |
|---|---|
| `rx=0` 且 `half=0` | 线上**完全没有信号** → 查接线/对方没发 |
| `rx=0` 且 `half>0` | 收到数据但都是半帧 → **波特率或线路质量**问题 |
| `rx>0` 且 `bad>0` | 有帧但 JSON 解析失败 → 字段名/转义问题 |

## 3. 日志（SD 卡 `logs/YYYYMMDD.csv`）

**双流合一**：遥测行与事件行写在同一个文件，共用时间戳，便于确定因果。

### 3.1 列定义

```
ts,ms,kind,name,tin,hin,tout,hout,ah_in,td_in,tset,rhset,mode,cool,heat,hum,light,fan,tfan,fault
```

| 列 | 说明 |
|---|---|
| `ts` | ISO8601 时间（未对时则为 1970） |
| `ms` | 开机毫秒数（**即使没对时也是准确的**） |
| `kind` | `T` = 遥测行，`E` = 事件行 |
| `name` | 遥测行为空；事件行为事件名 |
| 其余 | 与 §2.1 遥测字段对应；事件行留空 |

### 3.2 事件名

| 事件 | 触发 |
|---|---|
| `BOOT` | 开机 |
| `LINK_UP` / `LINK_LOST` | 链路建立 / 断开（断链时时间戳照盖，内容标 LINK_LOST） |
| `MODE_CHG` | 模式变化 |
| `HEAT_ON/OFF` `COOL_ON/OFF` `HUM_ON/OFF` `LIGHT_ON/OFF` `FAN_ON/OFF` `TFAN_ON/OFF` | 执行器动作（**由遥测差分生成**） |
| `FAULT` | 故障位变化 |
| `AI_SICK_MILD_<pct>` / `AI_SICK_SEVERE_<pct>` | AI 判定病蚕比例 |
| `AI_MOTION_REST` | AI 判定异动，降补光 |

### 3.3 采样周期

| 状态 | 周期 |
|---|---|
| 平时 | 5 s |
| 录像中 | 10 s（录像优先，减少写盘干扰） |

> 注意：Kconfig 里的 `LOG_INTERVAL_SEC=60` **已不生效**，实际是代码里的 5 s/10 s。

## 4. AI 决策规则（`ai_policy.c`）

| 条件 | 动作 | 备注 |
|---|---|---|
| `conf < 0.50` | **不动作** | 置信度门槛 |
| `sick_ratio ≥ 15%` | 降湿 8%（下限 45%）、升温 0.5 °C、补光、**强通风 5 min** | 重度 |
| `sick_ratio ≥ 5%` | 降湿 5%（下限 50%）、升温 0.5 °C、补光 | 轻度 |
| `motion > 0.30` 连续 3 帧 | 降补光 | 异动 |
| `count == 0` 持续 60 s | 关补光 | 空箱 |
| 任何动作后 | **冷却 120 s** | 防来回抖 |

### ⚠️ 已知缺陷：补光档位语义不匹配

AI 层发的是 `{"light_level":100}` / `50` / `128`（当成百分比），
但 STM32 侧 `light_level` 是 **0~4 档（每扇区点亮几颗）**：

```c
/* STM32 main.c */
#define WS2812_LEVEL_MAX  4u      /* 档位 = 每扇区灯珠数 */
if (level > WS2812_LEVEL_MAX) level = WS2812_LEVEL_MAX;   /* 100/50/128 全被夹到 4 */
```

**后果**：50、100、128 全部等于"满亮"，只有 `0`（关灯）有效。
所以"异动 → 补光降到 50%"实际是**开满**，效果与意图相反。

**修法（二选一）**：
1. P4 侧改成发档位：`{"light_level":2}`（快，但只有 5 档）
2. STM32 侧增加亮度百分比命令 `{"light_pct":0~100}`（推荐，配合 `light_r/g/b` 一起做）

## 5. 补光颜色协议（规范已定，STM32 侧未实现）

完整规范：`D:\stm32work\BS1\docs\补光调色规范.md`

摘要：

```json
{"light_r":255,"light_g":190,"light_b":110}
```

- 每通道 **40~255**（低于 40 单色不可见，色相会失控）
- 三个键可单独给，未给的不变
- 5 秒内只接受一次
- 灯珠字节序 **GRB**：`(g<<16) | (r<<8) | b`
- 遥测回传 `lr/lg/lb` 供闭环判收敛

## 6. 常见问题速查

| 现象 | 先查 |
|---|---|
| `ping` 通但网页打不开 | `/stream` 是不是占住了 httpd（应已修，异步 handler） |
| 录像文件 0 字节 | 有没有 `fsync`；目录项大小是否更新 |
| 文件名是 `19700101_*` | 没调 `/time?epoch=` |
| 播放器打不开但 ffmpeg 能读 | `avih.flags` 是否 0x10 而文件无 `idx1` |
| 视频时长比实际长 | `strh` 的 scale/rate 与 `avih.usPerFrame` 是否一致 |
| `sdmmc_init_ocr ... 0x107` | 片内 LDO 通道 4 有没有使能 |
| UART `rx=0 half=0` | GPIO38 是不是被当成 RX 了（那是 console） |
| 画面偏蓝 | 补光灯 R=G=B 天然 8000–10000 K；改配比，别改 CCM |
